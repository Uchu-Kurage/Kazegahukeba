# Kazegahukeba（風が吹けば）

終わりゆく世界の最後の夏（8/31 に世界が終わる）を過ごす、2Dドットの ADV 寄り RPG。
このリポジトリは **まず「一日が回る骨組み」だけ** を動かすための最小構成です。
物語・キャラ・ドット絵・エンディングは、この骨組みが動いてから足していきます。

## いま動くもの（最小の核）

本編は『ぼくのなつやすみ』方式の散策（FieldScene）です。道でつながった画面を自由に歩き回り、
目的地で人と過ごすときだけ枠を使います。

```
【タイトル Title】はじめる／（つづきから）／エンディング記録／記録を消す
        ↓ はじめる（＝家から朝スタート）
【散策 FieldScene】道の上を歩き、画面端の出口で隣の画面へ（全9画面／移動は無料）
   人・場所に近づいて［E］＝「過ごす」→ ここで枠を消費して会話・節目（Story/Dialogue）
        ↓ 午前 → 午後（2枠）
   夜：特別な夜があれば発生／無ければ［E］で就寝 → 翌朝は家から
        ↓ 8/31 を越える
【エンディング Ending】結末を再生 → 到達を記録 → 全到達で「9月1日」（裏エンド）解放 → タイトルへ
```

> 旧UI（`Town`＝地図選択／`Place`＝場所内探索）は散策に置き換わりました（コードは当面残置）。

- 40日間のカレンダー制（8/1 起点、`GameState.TOTAL_DAYS` で日数を調整可能）
- 一日 = 午前 / 午後（行動枠）＋ 夜（基本は振り返り）
- 特別な夜（花火・夏祭り。特定日付のみ）＝夜に行動が発生。夏祭り／最後の花火は「誰と過ごすか」を選び、
  その相手の関係値が上がり夜フラグが立つ（`data/Nights.gd`）。選ばなかった相手とは過ごせない（時間制）
- 街で行き先を **選択** → その場所の中へ移動して探索 → 過ごすとその枠を消費（他へは行けない）
- 一人で過ごす場所（町をぶらつく／畦道を歩く／家）＝相手なし・関係値は上がらないが枠は消費する
  正当な選択肢。誰とも深く結ばれない周は「関わりの総量」で記録者エンド二種（見届けた／ひとり）に分岐
- 過ごさずに出口から戻れば、同じ枠で別の場所を選び直せる
- 予定なしのスキップ（街で［Q］。枠は消費する）
- 場所に紐づくキャラの関係値を +1 する仮ロジック（`GameState.affinity`）
- 40日を越えると「世界の終わり」→ もう一度夏を始める（周回）

## 操作

| キー | 動き |
|------|------|
| WASD / 矢印キー | 街：行き先カーソルの移動 ／ 場所の中：歩行 |
| E（Space / Enter） | 中へ入る・話す・会話送り・カレンダーをめくる・特別な夜を始める・戻る・周回リスタート |
| Q | 街：予定なしでスキップ ／ 場所の中：過ごさず街へ戻る |
| F3 | 【デバッグ】ルート到達状況オーバーレイの表示切替（各ルートの到達節目・関係値・立場・背景フラグ・葵の今日の居場所） |
| F4 | 【デバッグ】いまの状態で即エンディング判定へ（集中／掛け持ちの分岐確認用） |
| F5 | 【デバッグ】裏エンド（9月1日）を強制再生（解放条件を無視・検証用） |
| F6 | 【デバッグ】散策画面（河原と土手）へ（第6弾 §1：歩く→出口の反応の確認用） |

## 動かし方

1. **Godot 4.6** でこのフォルダ（`project.godot` のある場所）を開く。
2. 初回はアセットのインポートが走る（少し待つ）。
3. ▶ 実行（F5）でメインシーン `scenes/Town.tscn` が起動する。

> **見た目は仮です。** プレイヤーも場所も、いまは四角い「プレースホルダ」で描いています
> （アートが無くても動かせるように）。ドット絵は後から `Sprite2D` /
> `AnimatedSprite2D` / `TileMapLayer` に差し替えていきます。

> **日本語フォント**は `assets/fonts/NotoSansJP-Regular.ttf`（Noto Sans JP / OFL 1.1）を
> 同梱し、`project.godot` の `gui/theme/custom_font` で全体に適用しています。

## 設計の考え方（初心者向けメモ）

UIをボタン→1画面探索→2階層マップと変えても、**日付や好感度を持つ `GameState` は一切
変えていません。** これが「状態（モデル）と表示（ビュー）を分ける」設計の効き目です。

- **状態は `GameState` が唯一の持ち主。** 日付・時間帯・好感度・フラグと、
  `午前 → 午後 → 夜 →（めくる）→ 翌朝` を進める状態機械。ここはUIもマップも知らない。
- **シーンをまたいで生き残るもの＝ Autoload。** `GameState`（状態）・`Nav`（遷移）・
  `HUD`（常時UI）は Autoload なので、街と場所を行き来しても中身が保たれる。
  だから街↔場所の遷移は「シーンを差し替えるだけ」で成立する。
- **層ごとに操作を分ける。** 街(Town)は歩かない選択画面（カーソルで行き先を選ぶ）。
  場所(Place)は歩ける探索画面で、歩行系の共通土台 `ExploreMap`（プレイヤー配置・対象への
  出入り検知・入力受け）を継承する。操作キーの登録は `Controls`（Autoload）に集約。
- **シグナルで疎結合に。** 状態が変わると `GameState` が `day_changed` / `phase_changed`
  を emit し、`HUD` が受けて表示し直す。UIを増やしても購読するだけ。

- [x] 会話中の選択肢（返答で好感度／フラグが動く。`then` で会話が枝分かれ）
- [x] フラグ／好感度によるエンディング分岐（`Endings.pick`）＋周回セーブ（全到達で裏エンド）
- [ ] 会話の分岐：日付・好感度・フラグでセリフ自体を変える（`Dialogues.for_location` に条件を追加）
- [x] タイトル画面（はじめる／エンディング記録＝図鑑／記録を消す）
- [x] 中盤の A/B/C（立場）を route 別に選び、エンディングの主軸に反映（`GameState.stance{}`）
- [x] 三ルート共通の器（`Routes`＋`Story`）＝ルート追加はデータ追加で済む（コード分岐なし）
      ／相手の枠を選んだときだけ、前提フラグ・関係値・時期を満たした次の1件が進む

> **BGM／効果音**：音源ファイルが無くても、`AudioManager` がコードで合成して鳴らします。

> あればそちらを優先します。

> 到達エンドは `user://save.cfg` に残るので、全ノーマル到達で裏エンドが流れます。
